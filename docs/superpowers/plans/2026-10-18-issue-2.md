# Suites du postmortem (issue #2) — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** corriger les cinq défauts relevés par l'issue #2 : zone de dépôt accessible, identité stable d'un fichier réajouté, relecture du seul outil touché, choix de l'outil affiché après un ajout, aucune erreur de console en `file:`.

**Architecture:** `src/sources.js` porte la logique pure : identité d'un fichier, choix entre deux versions, fichiers mis de côté (`dups`), outils touchés, fusion des résultats (`mergeRuns`). `src/main.js` l'utilise : il n'envoie au worker que les items des outils touchés, fusionne les bilans, choisit l'outil affiché et ne demande pas d'illustration en `file:`. Le worker ne change pas.

**Tech Stack:** JavaScript ES modules sans dépendance, `node:test`, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-18-issue-2-design.md`

## Global Constraints

- Aucune dépendance ajoutée (pas d'axe-core) ; aucune requête réseau depuis la page.
- Identité : Codex `codex:<sessionId>` ; Claude `claude:<slug>:<kind>:<sessionId>:<file.name>`.
- À identité égale : le `.jsonl` l'emporte sur l'archive ; sinon le plus récent (`lastModified`), puis le plus gros ; à égalité, celui déjà retenu.
- Reçu : clé JSON `duplicates` inchangée ; libellé FR « doublons d'une session déjà lue », EN « duplicates of a session already read » ; masquée à l'écran à 0.
- Catégories d'illisibles par outil : `claude` → `claude` ; `codex` → `codex`, `compressed`.
- Un ajout suppose un résultat d'analyse en mémoire (`state.result` non nul) ; sinon c'est un premier dépôt, tous les outils sont lus.
- Outil affiché après un ajout : un outil touché qui n'avait aucune session avant et en a maintenant ; sinon l'outil affiché s'il est toujours proposé ; sinon le plus fourni. Premier dépôt : le plus fourni.
- En `location.protocol === 'file:'` : ni galerie ni `fetch` d'illustration.
- Commentaires en français, renvoi `(spec issue #2 § N)` ; commits en anglais `feat:`/`fix:`/`test:`, terminés par `Claude-Session: https://claude.ai/code/session_0192DpdSD1TXL3ZbPURJoh8q`.
- Branche `issue-2` depuis `main`. Pas de fusion, de push ni de commentaire sur l'issue sans accord de Jean-Paul.

## Review Focus

1. Un ajout qui touche un outil dont tous les fichiers deviennent illisibles : ses catégories d'illisibles viennent du nouveau résultat, même à zéro, jamais de l'ancien (test `mergeRuns`, tâche 3).
2. Un ajout partiel puis l'export JSON : le reçu exporté garde les illisibles et les fichiers examinés des outils non relus (e2e, tâche 3).
3. Une archive et son `.jsonl` dans un même lot : l'archive arrive maintenant jusqu'à `addBatch` (le filtre de `codex/files.js` disparaît) et doit être comptée en doublon, pas en « non reconnus » (test unitaire, tâche 2).
4. Le réajout d'un dossier dont un seul fichier a grandi, pendant qu'un autre outil est affiché : pas de double comptage, et l'outil affiché ne change pas (e2e, tâches 2 et 4).
5. Le fichier autonome ouvert en `file:` après une analyse : la carte s'affiche sans illustration et sans erreur de console (e2e, tâche 5).

// Identité d'un fichier de session, stable quand il grandit (spec issue #2 § 3). Les fichiers de
// sous-agents Claude partagent le sessionId de leur session parente : leur nom les distingue.
const identity = (it) => (it.tool === 'codex' ? `codex:${it.sessionId}` : `claude:${it.slug}:${it.kind}:${it.sessionId}:${it.file.name}`);
// a vaut-il mieux que b, à identité égale ? Le .jsonl l'emporte sur l'archive, puis le plus récent,
// puis le plus gros ; à égalité, b (déjà retenu) reste (spec issue #2, décision 2).
function better(a, b) {
  if (!a.zst !== !b.zst) return !a.zst;
  if (a.file.lastModified !== b.file.lastModified) return a.file.lastModified > b.file.lastModified;
  return a.file.size > b.file.size;
}

// « Ajouter un dossier » : chaque lot déposé est trié seul, avec son propre contexte (racine, projects/),
// puis ajouté aux items déjà retenus. Un ajout ne reclasse jamais les fichiers d'un lot précédent.
// Une session n'est retenue qu'une fois par identité (spec issue #2 § 3).
// added : items nouveaux ou remplaçants ; touched : leurs outils ; dups : clés des fichiers mis de côté.
export function addBatch(items, entries) {
  const seen = new Set(items.map((it) => keyOf(it.file)));
  const byId = new Map(items.map((it) => [identity(it), it]));
  const fresh = new Set();
  const dups = [];
  for (const it of classify(entries)) {
    const k = keyOf(it.file);
    if (seen.has(k)) continue; // même fichier atteint par deux chemins
    seen.add(k);
    const id = identity(it), held = byId.get(id);
    if (held && !better(it, held)) { dups.push(k); continue; }
    if (held) { dups.push(keyOf(held.file)); fresh.delete(held); }
    byId.set(id, it); fresh.add(it);
  }
  return { items: [...byId.values()], added: fresh.size, touched: new Set([...fresh].map((it) => it.tool)), dups };
}

- [ ] **Step 2 : `mergeRuns`**

`src/sources.js`, à la fin :

```js
// Catégories d'illisibles du reçu, par outil.
const UNREADABLE = { claude: ['claude'], codex: ['codex', 'compressed'] };

// Un ajout ne relit que les outils touchés : bilans et illisibles des autres outils sont repris du
// résultat précédent (spec issue #2 § 4). prev nul : premier dépôt.
export function mergeRuns(prev, next, touched) {
  if (!prev) return { reports: next.reports, unreadable: next.unreadable || {} };
  const reports = {}, unreadable = {};
  for (const [tool, r] of Object.entries(prev.reports)) if (!touched.has(tool)) reports[tool] = r;
  for (const [tool, cats] of Object.entries(UNREADABLE)) {
    if (touched.has(tool)) continue;
    for (const k of cats) if (prev.unreadable && prev.unreadable[k]) unreadable[k] = prev.unreadable[k];
  }
  Object.assign(reports, next.reports);
  Object.assign(unreadable, next.unreadable || {});
  return { reports, unreadable };
}
```

// Outil choisi : au premier dépôt, le plus fourni ; après un ajout, l'outil que le lot vient d'apporter,
// sinon celui déjà affiché (spec issue #2 § 5).
function setReports(reports, add) {
  state.reports = reports;
  const has = (r, k) => !!(r && r[k] && r[k].volume.sessions > 0);
  const withSessions = Object.keys(reports).filter((k) => has(reports, k));
  state.tools = (withSessions.length ? withSessions : Object.keys(reports))
    .sort((a, b) => reports[b].volume.sessions - reports[a].volume.sessions);
  let tool = state.tools[0];
  if (add) tool = state.tools.find((k) => add.touched.has(k) && !has(add.before, k))
    || (state.tools.includes(state.tool) ? state.tool : tool);
  selectTool(tool);
  show('report');
}
